# Tomcell Seating Frontend

Фронтенд рассадки TomCell: библиотека ядра, стенд конфигуратора залов и встраиваемый виджет
продажи мест. Репозиторий самодостаточен: собирается и тестируется локально без доступа к
другим репозиториям проекта.

## Состав

| Каталог | Пакет | Что это |
|---|---|---|
| `libs/seating` | `@tickets/seating` | Ядро: модель геометрии, валидация, кодеки, два рендерера (сцена и редактор), типизированные клиенты API конфигуратора и продаж, SDK встраивания виджета |
| `apps/seating-lab` | `@tickets/seating-lab` | Рабочий стенд: конфигуратор залов организатора, административный справочник, витрина покупки, тестовый сайт-хост виджета, мобильный WebView-хост, макет тестовой оплаты |
| `docs/` | — | Архитектура, инструкция запуска стенда, справочник контракта backend |

Библиотека распространяется исходниками (`exports` указывает на `.ts`): приложение-потребитель
собирает её своим бандлером, отдельной сборки у неё нет — проверяется типами и тестами.

## Быстрый старт

```bash
npm install
npm run dev          # стенд конфигуратора — http://localhost:4200
npm run dev:site     # второй экземпляр для кросс-доменного встраивания — http://localhost:4300
```

Требуется Node.js 22+ и запущенный backend TomCell (по умолчанию `http://localhost:5057`,
транзакционный профиль Web; как его поднять — [`docs/run-and-stand.md`](docs/run-and-stand.md)).

Остальные команды:

```bash
npm test             # vitest: 207 тестов библиотеки + 96 тестов стенда
npm run typecheck    # tsc -b для обоих пакетов
npm run lint         # eslint
npm run build        # production-сборка стенда (страницы index/widget/webview-host/mock-payment/site-host)
```

## Что открыть в стендe

- **Конфигуратор** (`http://localhost:4200`) — три поверхности: организатор (свои залы и схема
  мест), администратор (справочники и модерация), витрина (покупательский просмотр). Управление
  инструментами, единицы схемы, проверка схемы и подложка PDF — в
  [`apps/seating-lab/README.md`](apps/seating-lab/README.md).
- **Тестовый сайт с виджетом** (`http://localhost:4300/site-host.html?occurrenceId=<показ>`) —
  изображает сайт организатора, встраивающий виджет продаж через `mountSeatingWidget`
  (кросс-доменно, с автоподстройкой высоты iframe). Журнал страницы показывает события,
  которые получает встраивающий сайт.
- **Мобильный хост** (`webview-host.html`) — статическая страница для Flutter/React Native
  WebView с нативным мостом; примеры кода обеих платформ — в README стенда.
- **Макет оплаты** (`mock-payment.html`) — страница, на которую виджет отводит покупателя в
  тестовом режиме; подтверждает или отклоняет оплату.

## Архитектура

Коротко: один источник знаний о схеме (`@tickets/seating`), над ним два рендерера — сцена
покупателя и редактор организатора; виджет — отдельная страница, встраиваемая через iframe и
версионированный протокол сообщений. Подробно: [`docs/architecture.md`](docs/architecture.md).

## Контракт backend

Клиенты (`libs/seating/src/api.ts`, `libs/seating/src/sales-api.ts`) написаны по OpenAPI и
руководствам backend; копии руководств, определяющих контракт, лежат в
[`docs/backend/`](docs/backend/):

- `seating-configurator.md` — геометрия, редакции, этажи, подложка, проверка схемы, импорт G31;
- `sales.md` — цены, компоновка показа, инвентарь, бронь, заказ, оплата, билеты;
- `api-contract.md` — общие правила HTTP-контракта (идемпотентность, PATCH, деньги, ошибки).

Эти копии даны для справки разработчику фронта; авторитетный источник — репозиторий backend.

## Вход и полномочия

Вход в стенд — логин-пароль Keycloak либо готовый access token (см. README стенда, раздел
«Вход»). Организатору нужны полномочия `SeatingRead`/`SeatingManage`, администратору —
дополнительно `VenueRead`/`VenueManage`. Для покупки в тестовом режиме достаточно токена
покупателя, вставленного в панель встраивания site-host.
