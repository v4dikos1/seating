# Запуск и стенд

Как поднять фронтенд против backend TomCell и что проверить вручную.

## Предпосылки

- Node.js 22+, npm.
- Backend TomCell, запущенный через AppHost (`dotnet run --project src/AppHost` из корня
  backend-репозитория). Порт транзакционного профиля Web закреплён: `http://localhost:5057`;
  профиль чтения — 5157. AppHost сам поднимает PostgreSQL, Redis и MinIO и передаёт хостам
  их адреса.
- Если фон запущен иначе, адрес API меняется в стендe на экране входа (значение сохраняется
  в браузере).

## Порядок запуска

```bash
npm install

# терминал 1 — стенд
npm run dev            # http://localhost:4200

# терминал 2 — второй экземпляр для кросс-доменного встраивания
npm run dev:site       # http://localhost:4300
```

Оба экземпляра — одно и то же приложение; второй нужен, чтобы `site-host.html` встраивал
виджет с «чужого» origin, как это будет на настоящем сайте.

## Вход

Два способа (подробности — README стенда, раздел «Вход»):

1. **Логин-пароль Keycloak** — работает, только если адрес страницы разрешён клиенту в
   Keycloak. Клиенты провижинятся с redirect URI портов 8000/8001/3000, поэтому с
   `localhost:4200` браузер получит отказ до ответа — это ожидаемо.
2. **Готовый access token** — вставляется в форму входа. Полномочия сервер проверяет по
   базе, а не по токену: организатору нужны `SeatingRead`/`SeatingManage`, администратору
   дополнительно `VenueRead`/`VenueManage`.

## Сквозной сценарий для ручной проверки

Короткий проход «организатор → модерация → публикация → цена → покупка»:

1. Войдите организатором, создайте конфигурацию на пространстве, этаж с PDF-подложкой
   (две точки и расстояние — калибровка; размещение задаётся отдельно), разметьте зоны.
2. Проверьте схему (кнопка «Проверка»): критические находки блокируют запись,
   предупреждения подтверждаются явно; «Сверить с сервером» сравнивает с сохранённой
   редакцией.
3. Создайте событие с будущим показом; администратор одобряет его (модерация) — сессия
   администратора в отдельной вкладке; событие публикуется.
4. Привяжите схему к показу и примените ценовой шаблон (страница цен: шаблон → версия →
   применение; список версий и архивация там же).
5. Откройте `http://localhost:4300/site-host.html?occurrenceId=<id показа>`, вставьте токен
   покупателя в панель встраивания, выберите места, забронируйте и пройдите тестовую оплату
   (макет `mock-payment.html`). Журнал site-host покажет события брони и покупки; билет с
   адресом места появится в «Моих билетах».

Токен живёт ~5 минут: операции записи лучше делать сразу после входа; истёкший токен не
сбрасывает несохранённую схему — откроется окно повторного входа.

## Тестовая оплата

Тестовый режим включается контекстом виджета (`testMode: true`). Виджет создаёт бронь,
отводит на макет оплаты, который подтверждает или отклоняет платёж; повтор по ключу
идемпотентности перевыпускает ссылку оплаты открытой попытки. Изменение цены между выбором
и бронью даёт `409 SalesPriceChanged` с актуальной суммой (`currentTotal`).

## Проверки перед передачей изменений

```bash
npm run typecheck && npm run lint && npm test && npm run build
```

Все четыре команды обязаны проходить; тесты и типы — в обоих пакетах.
